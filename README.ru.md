# teachme

[![validate](https://github.com/Vlad175cm/teachme/actions/workflows/validate.yml/badge.svg)](https://github.com/Vlad175cm/teachme/actions/workflows/validate.yml)

Скил для [OpenCode](https://opencode.ai), который превращает конец каждой задачи в урок.

Обычно агент заканчивает так: «Готово. Исправил баг в `slug.py`». Из этого не понять, откуда взялся баг, что ещё можно было сделать и как проверить правку самому. **teachme** заставляет агента объяснить работу: решения, отвергнутые альтернативы, риски и что попробовать дальше.

> English version: [README.md](README.md)

## Что получаете

В конце любой задачи, где менялись файлы или запускались команды, агент печатает отчёт из девяти фиксированных блоков:

| # | Блок | На какой вопрос отвечает |
|---|------|--------------------------|
| 1 | Задача и результат | Что просили и что теперь работает |
| 2 | Что сделано | Каждое изменение, по файлам, с причиной |
| 3 | Как я это делал | Реальный ход работы, включая тупики |
| 4 | Почему так, а не иначе | Альтернативы и почему они проиграли |
| 5 | Куда смотреть в коде | Карта: файл → роль → ключевые функции |
| 6 | Новые понятия | Термины и API, встреченные в задаче |
| 7 | Как проверить самому | Команды для копирования и ожидаемый вывод |
| 8 | Риски и ограничения | Что может сломаться и что не покрыто |
| 9 | Что изучить дальше | Конкретные следующие шаги |

Тот же текст сохраняется в `$HOME/ai-devlog/ГГГГ-ММ-ДД_ЧЧММ_<проект>.txt`, так что рядом с проектами копится журнал обучения, по которому можно искать.

## Установка

```bash
git clone https://github.com/Vlad175cm/teachme.git
cd teachme
./install.sh
```

Установщик:

1. копирует `skills/learning-report/` в `~/.config/opencode/skills/`;
2. добавляет размеченный блок в `~/.config/opencode/AGENTS.md` — с бэкапом и без дублей при повторном запуске.

`./install.sh --no-agents` — поставить только скил. Перезапуск OpenCode не нужен: скилы и `AGENTS.md` перечитываются автоматически.

### Вручную

Скопируйте `skills/learning-report/` в `~/.config/opencode/skills/` и добавьте в `~/.config/opencode/AGENTS.md`:

```markdown
## Обучающий отчёт в конце задачи

Пользователь учится на работе агента. Поэтому перед финальным сообщением в любой задаче,
где ты менял файлы, конфиги или запускал команды:

1. Загрузи скил `learning-report` инструментом `skill` и следуй ему.
2. Отчёт — по-русски, в чат.
3. Сохрани копию в `.txt`-файл в `$HOME/ai-devlog/` и укажи путь последней строкой.

Отчёт не сокращай и блоки не пропускай, даже если задача кажется простой.
```

## Зачем нужен AGENTS.md

Скилы в OpenCode загружаются лениво: модель видит только имя и описание и может ни разу не открыть тело. `AGENTS.md` находится в контексте каждого запроса и работает триггером: «в конце каждой задачи загрузи этот скил».

Один скил — это предложение. Скил плюс `AGENTS.md` — это поведение по умолчанию.

## Настройка

| Что | Где | Как |
|-----|-----|-----|
| Язык отчёта | `SKILL.md`, `AGENTS.md` | заменить «по-русски» на нужный язык |
| Каталог журнала | `SKILL.md` → `Файл` | поменять `$HOME/ai-devlog/` |
| Блоки отчёта | `SKILL.md` → `Обязательные блоки` | добавить или убрать, затем обновить чек-лист в `Перед отправкой` |
| Область действия | блок в `AGENTS.md` | добавить условие, например «только в git-репозиториях» |

Скил и блок в `AGENTS.md` держите согласованными: блок только запускает, формат задаёт скил.

## Проверка

```bash
ls ~/.config/opencode/skills/learning-report/SKILL.md
grep -c '<!-- teachme:begin -->' ~/.config/opencode/AGENTS.md   # должно быть 1
```

Затем попросите агента о небольшом изменении в любом проекте. Ожидаемо: девять заголовков `### 1.` … `### 9.`, последняя строка — путь к новому `.txt` в `~/ai-devlog/`.

## Удаление

```bash
rm -rf ~/.config/opencode/skills/learning-report
```

Затем удалите строки между `<!-- teachme:begin -->` и `<!-- teachme:end -->` в `~/.config/opencode/AGENTS.md`.
